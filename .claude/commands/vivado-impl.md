# Vivado Implementation Skill

Run AMD Xilinx Vivado place-and-route implementation, generate timing/utilization reports, and optionally write the programming bitstream.

## Usage

```
/vivado-impl [options]
```

**Options (provide in your message):**
- `bitstream=yes|no` — Also generate bitstream after implementation (default: `no`).
- `strategy=<name>` — Implementation strategy: `default`, `performance_explore`, `area_explore`, `power_opt` (default: `default`).
- `jobs=<n>` — Parallel jobs (default: 4).
- `checkpoint=<path>` — Start from an existing synthesis checkpoint (default: `checkpoints/synth.dcp`).

---

## What This Skill Does

1. Checks for a synthesis checkpoint (`checkpoints/synth.dcp`). Offers to run `/vivado-synth` first if missing.
2. Locates or generates `scripts/impl.tcl`.
3. Runs `vivado -mode batch -source scripts/impl.tcl`.
4. Parses implementation logs for timing violations and errors.
5. Reports WNS, WHS, WPWS, and resource utilization.
6. Copies bitstream to `bitstream/` if requested.

---

## Steps to Execute

### 1. Check prerequisites
```bash
which vivado || source /opt/Xilinx/Vivado/*/settings64.sh
ls checkpoints/synth.dcp || echo "WARNING: No synthesis checkpoint found — run /vivado-synth first"
```

### 2. Locate or generate `scripts/impl.tcl`

**Template: `scripts/impl.tcl`**
```tcl
# Vivado Implementation Script — auto-generated by /vivado-impl skill
set strategy     "Vivado Implementation Defaults"
set jobs         4
set gen_bitstream 0   ;# set to 1 to also write bitstream

# Open post-synthesis checkpoint
open_checkpoint checkpoints/synth.dcp

file mkdir reports checkpoints bitstream logs

# Optimise netlist
opt_design

# Power optimisation (optional — comment out if not needed)
# power_opt_design

# Place
place_design -directive $strategy

# Post-place physical optimisation
phys_opt_design

# Route
route_design -directive $strategy

# Post-route physical optimisation (helps close timing)
phys_opt_design

write_checkpoint -force checkpoints/impl.dcp

# ---- Reports ----
report_timing_summary \
    -max_paths 20 \
    -report_unconstrained \
    -warn_on_violation \
    -file reports/timing_summary.rpt

report_utilization          -file reports/utilization.rpt
report_power                -file reports/power.rpt
report_clock_utilization    -file reports/clock_utilization.rpt
report_drc                  -file reports/drc.rpt
report_io                   -file reports/io.rpt

# Check DRC for errors
set drc_violations [get_drc_violations -severity {Error}]
if {[llength $drc_violations] > 0} {
    puts "ERROR: DRC violations found — bitstream generation skipped."
    puts [join $drc_violations "\n"]
    exit 1
}

# Bitstream
if {$gen_bitstream} {
    write_bitstream -force bitstream/design.bit
    write_cfgmem -force \
        -format bin \
        -interface spix4 \
        -size 128 \
        -loadbit "up 0x0 bitstream/design.bit" \
        bitstream/design.bin
    puts "Bitstream written to bitstream/design.bit"
}

puts "Implementation complete."
```

### 3. Run implementation
```bash
mkdir -p checkpoints reports bitstream logs
vivado -mode batch -source scripts/impl.tcl -log logs/impl.log -journal logs/impl.jou 2>&1
```

### 4. Parse timing results
```bash
grep -E "^(ERROR|CRITICAL WARNING)" logs/impl.log | head -20
grep -E "(WNS|WHS|WPWS|TNS|THS)" reports/timing_summary.rpt | head -10
```

### 5. Report to user

Always report:
- **Timing summary table** (WNS, WHS, WPWS — all must be ≥ 0 for a clean implementation)
- **Utilization summary** (LUTs, FFs, BRAMs, DSPs, IO, routing congestion)
- **DRC violations** (errors block bitstream generation)
- Path to reports: `reports/`
- Path to checkpoint: `checkpoints/impl.dcp`
- Path to bitstream (if generated): `bitstream/design.bit`

## Timing Closure Guidance

When WNS < 0 (setup violation), suggest these strategies in order:

1. **Identify critical paths:**
   ```tcl
   report_timing -max_paths 10 -path_type full -file reports/critical_paths.rpt
   ```
2. **Try aggressive implementation directive:**
   - `strategy=performance_explore` or `AggressiveExplore`
3. **Add pipeline registers** to the failing paths in RTL.
4. **Check for missing multicycle path constraints** in XDC.
5. **Review clock domain crossings** — missing false paths inflate hold violations.
6. **Enable retiming:**
   ```tcl
   synth_design ... -retiming
   ```

When WHS < 0 (hold violation):
- Usually indicates missing XDC constraints for CDC paths.
- Add `set_false_path` or `set_max_delay -datapath_only` for async signals.

## Common Errors

| Error | Cause | Fix |
|---|---|---|
| `[Route 35-39] nets not completely routed` | Congestion / too many routing resources used | Try `strategy=congestion_sspe_explore`; reduce design size |
| `[DRC NSTD-1] unspecified I/O standard` | Pins without IOSTANDARD in XDC | Add `set_property IOSTANDARD LVCMOS33 [get_ports ...]` |
| `[DRC UCIO-1] unconstrained logic interface` | Top-level port not in XDC | Add pin location + IOSTANDARD for all ports |
| Bitstream fails after DRC errors | DRC errors not resolved | Fix DRC violations in `reports/drc.rpt` first |
