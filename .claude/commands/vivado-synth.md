# Vivado Synthesis Skill

Run AMD Xilinx Vivado synthesis for the current VHDL project in batch mode.

## Usage

```
/vivado-synth [options]
```

**Options (provide in your message):**
- `part=<part>` — Target device (e.g., `part=xcku5p-ffvb676-2-e`). Defaults to value in project TCL or prompts if missing.
- `top=<entity>` — Top-level entity name. Defaults to value set in project.
- `jobs=<n>` — Parallel synthesis jobs (default: 4).
- `strategy=<name>` — Synthesis strategy: `default`, `area`, `performance`, `power` (default: `default`).

---

## What This Skill Does

1. Verifies Vivado is available on `$PATH` (sources `settings64.sh` if needed).
2. Locates or generates `scripts/synth.tcl`.
3. Runs `vivado -mode batch -source scripts/synth.tcl`.
4. Parses the synthesis log for critical warnings and errors.
5. Reports resource utilization summary (LUTs, FFs, BRAMs, DSPs).

---

## Steps to Execute

When the user invokes `/vivado-synth`, perform the following:

### 1. Check environment
```bash
which vivado || source /opt/Xilinx/Vivado/*/settings64.sh
vivado -version
```

### 2. Locate or create the synthesis TCL script

Look for `scripts/synth.tcl`. If it does not exist, generate it from the template below, filling in `PART` and `TOP` from user options or by asking.

**Template: `scripts/synth.tcl`**
```tcl
# Vivado Synthesis Script — auto-generated by /vivado-synth skill
set part      "xcku5p-ffvb676-2-e"   ;# <-- update for your device
set top       "top_level"             ;# <-- update for your top entity
set jobs      4
set strategy  "Vivado Synthesis Defaults"

# Create in-memory project
create_project -in_memory -part $part

# Add RTL sources
foreach f [glob -nocomplain rtl/**/*.vhd rtl/*.vhd] {
    read_vhdl -vhdl2008 $f
}

# Add IP cores
foreach xci [glob -nocomplain ip/**/*.xci] {
    read_ip $xci
}

# Add constraints (for synthesis-time constraints only)
foreach xdc [glob -nocomplain constraints/*.xdc] {
    read_xdc $xdc
}

set_property top $top [current_fileset]

# Run synthesis
synth_design -top $top -part $part -flatten_hierarchy rebuilt
write_checkpoint -force checkpoints/synth.dcp

# Reports
file mkdir reports
report_utilization    -file reports/utilization_synth.rpt
report_timing_summary -file reports/timing_synth.rpt -warn_on_violation
report_clock_networks -file reports/clocks.rpt

puts "Synthesis complete."
```

### 3. Run synthesis
```bash
mkdir -p checkpoints reports
vivado -mode batch -source scripts/synth.tcl -log logs/synth.log -journal logs/synth.jou 2>&1
```

### 4. Parse results

After synthesis, check the log and report:
```bash
grep -E "^(ERROR|CRITICAL WARNING|WARNING)" logs/synth.log | head -40
grep -A 30 "Slice Logic" reports/utilization_synth.rpt
```

### 5. Report to user

Summarize:
- Pass / Fail status
- Any CRITICAL WARNINGs (especially timing, clock, or DRC related)
- Resource utilization table (LUTs, FFs, BRAMs, DSPs, IO)
- Path to full log: `logs/synth.log`
- Path to checkpoint: `checkpoints/synth.dcp`

## Common Synthesis Issues and Fixes

| Issue | Likely Cause | Fix |
|---|---|---|
| `[Synth 8-327] inferring latch` | Missing default in combinational process | Add default assignment before conditional logic |
| `[Synth 8-3352] multi-driven net` | Signal driven from multiple processes | Consolidate to single driver |
| `[Synth 8-5858] abstract datatype` | Non-synthesizable type used | Replace with `std_logic_vector` |
| `[Synth 8-256] cannot find operator` | Missing library/use clause | Add `use ieee.numeric_std.all;` |
| Clock not propagating | Missing `create_clock` in XDC | Define clock in constraints file |
| DSP not inferred | Operations split across processes | Restructure multiply-accumulate into one process |
